# 路线图：从现有原型到 v1.0

本页根据原始 v0.1 technical note、原计划差距审计及各版实测报告整理。
v0.6–v0.9 是补齐原计划缺口的后续工程安排；不是把所有新安排当作最初就承诺过的里程碑。
版本号代表交付范围，不能代替基准、能耗或算法新颖性的证据。

| 阶段 | 已交付 | 仍欠缺 |
|---|---|---|
| v0.1 | Python 图、固定抽样、误差和控制器原型 | 未证明数据库性能 |
| v0.2 | Neo4j/Cypher、微型数据、精确 COUNT、离线回退与教程 | 仅基础功能 |
| v0.3–v0.4 | 真实数据库计时、可复用抽样、NSGA-II 与穷举对照 | 没有能耗目标 |
| v0.5 | DLSS 启发的校准缩放、误差门控、滞回与档位 | 不是 NVIDIA DLSS，研究新颖性未建立 |
| v0.6 | SNAP 公开拓扑、50k/100k/200k、实际进程 RSS、共享查询路径比较 | 自定义 COUNT，不是正式 LDBC；未证明内存节省 |
| v0.7 | 构建成本感知、延迟构建、NSGA-II 去重与容量对照 | 未建立稳定整体加速 |
| v0.8 | 精确抽查、计时漂移隔离、独立校准恢复与完整恢复计费 | 抽查盲区与恢复成本高；只支持静态图 |
| v0.9（本轮） | 抽查间隔对照；单纯计时漂移的定向恢复 | 需跨故障相位、更多谓词/预算与拓扑验证 |
| v1.0（目标） | 能耗、完整比较与统一研究报告 | 尚未完成，以下为验收要求 |

## v1.0 前的工作顺序

1. **可靠性与成本**：量化抽查间隔的误差/检测延迟/成本，减少无需执行的全量恢复。
   先保留明确的故障类型和恢复前精确复核，再考虑自动调度；不能把盲区错误隐藏掉。
2. **能耗仪表**：检查此机器可读取的实际能量计数器或外部功率仪。
   明确 CPU package、数据库进程或整机的边界、采样/空闲基线、计数器回绕与背景负载。
   若硬件不可读，输出 unavailable 并记录原因；不得用延迟乘假定功率冒充测量。
3. **性能—能耗—精度目标**：只有取得可信 joules/request 后，才将能耗加入 NSGA-II。
   对相同工作负载、预算和准备成本比较 exact、固定档、穷举、NSGA-II 与自适应。
   报告独立重复和不利结果，区分离线优化、查询、构建、审计与恢复。
4. **标准工作负载与覆盖**：导入并核对 LDBC SNB 的数据/查询语义，先明确哪些 COUNT
   能采用现有估计器。多跳路径不能直接套用边 COUNT 的 `1/f²`。
   增加谓词稀疏度、故障发生相位、档位预算及图拓扑/规模的留出实验。
   未执行完整协议就标记“LDBC 子集/自定义工作负载”，不称合规基准。
5. **统一研究报告**：写清问题、算法/伪代码、系统边界、实验设计、基线、消融、
   全成本、失败情况、适用条件和复现步骤；用可核对的相关工作评估创新点。
   同步整理诚实的简历项目描述与演示。当前没有机器人或具身智能实验。

## v1.0 发布条件

- 原始实验保留，关键结果能从公开代码及私有原始记录复现。
- 图指纹、样本/拟合/校准/计时种子、测量边界和统计独立单位可追溯。
- 真实能耗测量存在，或醒目标注该验收项未完成；不能写成已实现能耗优化。
- 标准基准范围明确，精度保证与周期抽查的区别明确，跨图/更新能力不过度宣称。
- 测试、离线回退和 CI 通过；报告同时呈现成本上升、预算超限与失败情况。

本页会随实测更新。完整能耗、LDBC 和研究报告不能仅靠将版本号改成 1.0 完成。
