# 面试讲解：先讲清楚已经做成的部分

## 约一分钟的项目介绍

“我做了一个 Python 和 Neo4j 的图查询优化研究原型。问题是：当业务允许 COUNT
结果有一定误差时，能不能减少数据库扫描？我用可复用的节点抽样、独立误差校准和
自适应档位来选择样本量，再与真实 Neo4j 精确查询比较。在一个 5 万节点静态图的
6,000 对请求实验中，计入记录的训练和准备成本后，成本从 303 秒降到 226 秒，
比值约 1.34。实验允许 20% 相对误差，最大观察误差是 11.26%。我也做了两个规模
各 100 个新抽样轮次的精度检验，以及官方 LDBC 参考操作的语义验证。”

只在自己能复现和解释这些工作时使用上面第一人称。项目采用 AI 辅助开发；个人贡献
按实际参与描述，例如问题定义、Neo4j 配置、复现实验、结果分析或代码实现。

## 七个需要讲得清楚的问题

1. **数据是什么？** 主算法实验是合成静态图，FR/DE 国家属性的节点计数和两端都在
   同一国家的边计数。LDBC SF0.1 是另外一组数据库基准验证，不能混成同一个加速结果。
2. **为什么除以 f 或 f²？** 节点入样概率为 f；不同端点都入样的概率为 f²。
   因此把观察计数缩放回来。边之间有共享端点，误差仍相关；不能把边当成独立样本。
3. **怎么选档位？** 独立拟合数据确定误差尺度，独立校准数据覆盖所有已知档位；运行时
   看实际样本量是否支持误差预算，不足就升档。未知谓词回退精确查询。
4. **有没有偷看正确答案？** 训练和校准阶段需要精确答案，成本要计入。测试阶段的精确
   oracle 在选择之后才核对结果，不给控制器提供答案。
5. **1.34× 包含什么？** 记录的训练、联合拟合、样本准备、session 初始化和在线查询。
   图导入、profile 读取和测试 oracle 排除；训练阶段包含自身校验。阶段分开测量。
6. **为什么不是每种情况都更快？** 短流难以摊销准备成本；严格 5% 预算使样本变大、
   甚至回退精确查询。历史复用和增量统计在现有消融中也没有稳定优势。
7. **还欠什么？** 跨拓扑、非重复参数、并发更新与完整 LDBC 的自适应收益；零观察
   违例不是精度保证。“DLSS”是启发来源，当前没有 GPU/图像重建或神经网络成果。
