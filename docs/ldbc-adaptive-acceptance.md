# 完整 LDBC 自适应收益：后续验收，尚未完成

v0.19 已继续执行密集聚合筛选与 IC5 独立校准，见
[验证报告](v019-ldbc-aggregation.md)。IC5/IC6/IC12 官方参数仍以小计数为主；
IC5 自定义全窗口虽更密集，排名边界仍使所有近似档未通过校准，保留精确执行。
还补了 SF1 离线质量验证、独立新根节点确认、受控更新失效检查，以及最新实现的
完整参考文件回放。上述检查不等于完整混合负载的自适应收益。

当前 1.34× 结果是合成图的自定义 COUNT 长流。v0.18 跨拓扑/未见区间参数实验也属于
自定义 COUNT，不能充当 LDBC 加速证据。本页把用户要求保留为明确的下一条主线。

v0.18 已加入只读 IC3 消息入样原型，包含与官方查询的完整有序元组核对、
top-20 召回、漏人计数误差和精确候选基线。固定档可行性试验仍不能代替独立质量
校准、自适应策略或完整混合收益；见 [IC3 试验报告](v018-ldbc-ic3-sampling.md)。

该试验的官方参数结果全空，宽窗口非空压力测试中所有抽样档均未通过质量要求，
且消息 ID 获取方案慢于官方精确查询。因此当前适配器不得接入混合 driver。
先筛选较密集的聚合族（例如 IC5 的论坛帖子聚合，并先验证真实计数分布），再决定
是否实现独立校准。IC3 保留精确执行；不能为得到漂亮数据降低既定质量要求。
压力测试中 18 个国家计数有 13 个为 1、5 个为 2；真值为 1 时，75% 档保留一个
消息后放大为 1.333，已超过 20% 预算。适用查询族筛选应先于继续增加训练量。

## 两种实验契约

官方 SNB Interactive v1 的 29 类操作有精确结果契约；当前已有全参考验证与混合运行，
但此前混合服务成本没有改善。允许近似的研究扩展必须另报答案质量，不称正式认证成绩。
写入操作及完整资料等不适合聚合抽样的读取必须保留精确语义。

## 具体实施顺序

1. 已试验 IC3 的消息聚合：保留 Person/KNOWS 候选集合，对 Message 入样，计数按 1/f
   缩放。这里不能照搬节点与边一起入样的 1/f²。读取固定提交的官方查询与替代参数。
   该只读实现未通过可行性筛选，下一步先检查密集聚合族，保留相同完整元组质量原则。
2. 对通过筛选的聚合族独立拟合、校准、测试根节点/国家/日期参数。IC3 返回排名后的完整元组，因此除计数
   相对误差，还要检查 top-20 召回、名次变化、漏掉的候选及空结果；不能只验证一个 COUNT。
3. 在独立实验数据库测试快照和更新失效。Message 更新改变校准条件；失效期间回退精确
   或重新准备，全部恢复开销收费。原始 SF0.1 和学习数据库保留。
4. 仅在独立质量与总成本门控通过后，将操作适配器接入完整 29 类混合输入，其余类型执行精确查询。记录实际
   类型覆盖，避免“全启用”被误写成“全部实际执行”。最新 update1 修复的全文件回放已补。
5. 用相同初始快照、输入、操作混合和机器资源对照精确、固定档及自适应策略。保留失败
   调度审计和答案质量问题，计入训练、样本构建、更新维护、审计和恢复成本。
6. 同时报告加权服务成本和包含准备的生命周期成本。固定到达率 throughput 不能代表
   最大可持续容量；饱和能力需另设负载实验。不同拓扑/规模重新校准和零样本迁移分别报告。

完成条件是同条件混合对照获得实测收益，同时满足预先固定的质量要求。若总体更慢，
应报告不支持完整工作负载收益，不能用 IC14 单项加速或自定义 COUNT 的结果替代。
