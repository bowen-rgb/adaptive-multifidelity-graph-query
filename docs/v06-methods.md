# v0.6 方法与复现说明

目标：在同一张静态图上，比较节点 COUNT 和边 COUNT 的精度、耗时及选档方式。
本轮把两种 COUNT 的 fidelity 分开；一个配置是 `(f_node, f_edge)`，而不是
用一个档位同时控制两个查询。八档形成 64 种配置。

## 数据与查询

合成图沿用 v0.1 的随机生成器与五个国家标签，保留重复边记录。
公开图来自 [Stanford SNAP Facebook](https://snap.stanford.edu/data/ego-Facebook.html)。
无向边按端点顺序规范化，只存一次；按完整图上的度数分为五组。
公开图的 `country` 字段只是复用接口的分组属性，不代表真实国家。
查询分别统计该组节点数、两个端点都属于该组的边记录数。
这是公开拓扑上的自定义查询，还没有实现官方 LDBC 查询集。

## 估计与校准

每个节点生成独立均匀随机数 `u`，`u < f` 时进入该档抽样。
节点原始估计为 `sampled_count / f`；两个不同端点同时入样的概率为 `f²`，
所以边原始估计为 `sampled_count / f²`。图中的自环在生成或导入时被排除。

拟合阶段用 20 个种子学习每档、每个 COUNT 类型的乘法修正系数。
校准阶段另用 40 个种子，对一个种子下所有分组、近似档位及两类 COUNT 的
标准化残差取最大值，再取排序后的第 39 个值形成联合校准阈值。
精确档始终用修正系数 1、误差界 0。模型不保存查询的精确答案用于在线还原。
修正并不保证每个样本更准确；校准界也不是每次查询的误差保证。

拟合种子 2000–2019；校准种子 3000–3039；计时种子 8000–8002；
留出评估种子 9000–9004。同一张图内区分这些种子，不能替代跨图验证。

## 静态选择与自适应选择

固定档、穷举、NSGA-II 和自适应算法都使用相同冻结修正系数、同一查询接口。
穷举从满足两个校准误差预算的配置中选预估查询成本最低者。
NSGA-II 优化三个目标：预估查询成本、节点校准误差界、边校准误差界。
每个分组运行十个搜索种子；在线配置只取预先指定的种子 0 的最终前沿。
其他种子和穷举前沿用于诊断，不能补充在线前沿。64 个候选很少，
不能据此声称 NSGA-II 比穷举更高效；其目标函数是计时表查找。

自适应控制器第一次从两个 5% 草稿开始，分别检查误差预算和样本计数。
节点样本不足 20、边样本不足 10，或校准界超预算，就执行更高档查询。
预算收紧立即升档；连续三次需要较低档才降档。
分组或抽样 generation 改变时重置历史。模型图指纹或分组不匹配时查精确结果。
所有草稿和重查都计入请求耗时。它依据冻结校准表选档，尚不在线学习。

## 成本与内存边界

本轮选档目标是已有抽样时的查询成本。真实请求耗时包括状态检查、
两个 COUNT、修正以及控制器开销。各模式共享同一抽样，执行顺序随机打散。
每个种子下，一条独立模式流包含五轮档位预算，每轮每个分组查询三次。
构建成本按独立流场景分摊：用过任何抽样调用（包括随后弃用的草稿）就承担
完整构建成本；全程只执行精确调用则不需要构建。
导入、校准、计时表准备及优化启动成本另列，尚未摊入整套系统的启动成本。

RSS 每 100 ms 采样，分别记录 Python 与 Neo4j 进程；它是整个进程的驻留内存，
不是 Python 对象分配量，也不是单张图的占用。Neo4j 保留了旧实验数据，
因此不能通过本轮数据宣称低档减少数据库内存。短暂峰值可能落在采样间隔之间。

完整原始数据、分阶段内存、配置选择及升档轨迹都保存在 `results/neo4j/deep-v06/`。
结果报告由 `python scripts/report_deep.py` 生成，并使用种子块而非重复请求
进行 bootstrap。五个种子块只是当前运行的初步证据。

仍需：复杂遍历与 LDBC、冷缓存/独立重复实验、在线误差审计与漂移处理、
能耗测量、消融实验及与既有方法的创新性比较。
